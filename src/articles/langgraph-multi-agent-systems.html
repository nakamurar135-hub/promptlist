はじめに

前回の記事では、AIエージェントが自律的に思考し行動するためのReActフレームワークについて学びました。単一のエージェントでも多くのタスクをこなせますが、現実世界の複雑な問題には、複数の専門家が協力し合うように、複数のAIエージェントが連携して取り組む「マルチエージェントシステム」が有効です。

本記事では、LangChainの強力な拡張機能であるLangGraphを用いて、複数のAIエージェントが協調して複雑なタスクを解決するシステムの構築方法を解説します。リサーチ、分析、執筆といった異なる役割を持つエージェントを連携させ、より高度な自動化を実現する手法を学びましょう。

LangGraphは、エージェント間の複雑なやり取りをグラフ構造で定義できるため、システムの設計とデバッグが容易になります。この記事を通じて、皆さんはマルチエージェントシステムの設計思想を理解し、実際に動くリサーチチームを構築できるようになるでしょう。

マルチエージェントシステムの設計思想

マルチエージェントシステムは、単一の強力なAIではなく、それぞれが特定の能力や役割を持つ複数のAIエージェントが協力し合うことで、より大きな目標を達成するアプローチです。

シングルエージェントの限界とマルチエージェントの可能性

シングルエージェントは、与えられたタスクに対して一貫した思考と行動を繰り返しますが、その能力は単一のLLMと利用可能なツールの範囲に限定されます。複雑な問題や多角的な視点が必要なタスクでは、以下のような限界に直面することがあります。

  • 専門性の欠如: 一つのエージェントが全ての分野に精通することは難しい。
  • タスクの複雑性: 非常に複雑なタスクを単一のエージェントで処理すると、思考が発散したり、効率が低下したりする。
  • エラー耐性: 単一のエージェントが失敗すると、システム全体が停止するリスクがある。

これに対し、マルチエージェントシステムでは、各エージェントが特定の専門分野を担当し、互いに情報を共有・協力することで、これらの限界を克服し、より堅牢で高性能なシステムを構築できます。

専門家（エージェント）の役割分担

マルチエージェントシステムの鍵は、タスクを細分化し、それぞれのサブタスクに最適なエージェントを割り当てることです。例えば、記事執筆タスクであれば、以下のように役割を分担できます。

  • リサーチャーエージェント: Web検索ツールを駆使して、必要な情報を収集する。
  • アナリストエージェント: 収集した情報を分析し、構造化されたデータや洞察を抽出する。
  • ライターエージェント: 分析結果を基に、指定された形式で記事を執筆する。
  • レビューアーエージェント: 執筆された記事を校正し、品質をチェックする。

このように役割を明確にすることで、各エージェントは自身の専門性を最大限に発揮し、全体として高品質な成果物を生み出すことができます。

協調とコミュニケーションのパターン

複数のエージェントが効果的に機能するためには、適切な協調とコミュニケーションのメカニズムが必要です。主なパターンとしては、以下のようなものが挙げられます。

  • シーケンシャル（直列）: あるエージェントの出力が次のエージェントの入力となる、パイプライン型の連携。
  • パラレル（並列）: 複数のエージェントが同時に異なるサブタスクを実行し、後で結果を統合する。
  • 階層型: 上位のエージェントが全体計画を立て、下位のエージェントに具体的なタスクを指示する。
  • 議論型: 複数のエージェントが互いの意見を交換し、合意形成を図る。

LangGraphは、これらの複雑な協調パターンをグラフ構造として直感的に表現し、実装することを可能にします。

LangGraph入門

LangGraphは、LangChainを基盤としたライブラリで、複数のLLMやツール、エージェントを組み合わせて、複雑なステートフルなアプリケーションを構築するためのフレームワークです。特に、エージェント間のやり取りをグラフとして定義できる点が特徴です。

グラフベースのアプローチとは

従来のプログラミングでは、処理の流れを順次的に記述することが多いですが、LangGraphでは処理の各ステップを「ノード」、ノード間のデータの流れや制御を「エッジ」として表現します。これにより、条件分岐やループ、並列処理といった複雑なワークフローを視覚的かつ柔軟に設計できます。

例えば、あるエージェントが特定の条件を満たした場合にのみ次のエージェントに処理を渡す、といった動的なフローも容易に実現できます。

ノード（エージェント）とエッジ（遷移）の定義

LangGraphにおける主要な構成要素は以下の通りです。

  • ノード (Nodes): グラフの各ステップを表します。これはLLMの呼び出し、ツールの実行、カスタムPython関数など、任意のアクションを実行するエージェントや関数になります。
  • エッジ (Edges): ノード間の接続を表し、データの流れや制御の遷移を定義します。条件付きエッジを使用することで、ノードの出力に基づいて次のノードを動的に決定できます。
  • State (状態): グラフ全体で共有される情報です。各ノードは状態を読み書きでき、これによってエージェント間のコミュニケーションや情報の引き継ぎが行われます。

StatefulGraph の概念

LangGraphの核心は、StatefulGraphです。これは、グラフの実行中に状態を保持し、各ノードがその状態を更新できることを意味します。これにより、エージェントは過去の対話履歴やタスクの進行状況を記憶し、それに基づいて次の行動を決定できるようになります。

例えば、リサーチエージェントがWeb検索で得た情報を状態に書き込み、アナリストエージェントがその状態から情報を読み取って分析する、といった連携が可能です。

実装：リサーチチームの構築

それでは、LangGraphを使って、リサーチ、分析、執筆を行うマルチエージェントシステムを構築してみましょう。今回は、特定のトピックについてWebで情報収集し、その情報を分析してレポートを作成するチームを想定します。

役割定義：リサーチャー、アナリスト、ライター

まず、各エージェントの役割と責任を明確にします。

エージェント名 役割 主なツール
リサーチャー 指定されたキーワードでWeb検索を行い、関連情報を収集する。 Web検索ツール（例: WikipediaQueryRun）
アナリスト リサーチャーが収集した情報を分析し、要点を抽出し、構造化する。 なし（LLMの推論能力のみ）
ライター アナリストの分析結果を基に、指定された形式でレポートを執筆する。 ファイル書き込みツール（例: write_file）

各エージェントのプロンプトとツールの設定

各エージェントには、その役割に応じたプロンプトとツールを設定します。ここでは、前回の記事で作成したWeb検索ツールとファイル書き込みツールを再利用します。

```python from langchain_openai import ChatOpenAI from langchain.agents import AgentExecutor, create_react_agent from langchain import hub from langchain.tools import tool from langchain_community.tools import WikipediaQueryRun from langchain_community.utilities import WikipediaAPIWrapper from langgraph.graph import StateGraph, END from typing import TypedDict, Annotated, List import operator # LLMの初期化 llm = ChatOpenAI(model="gpt-4o-mini", temperature=0) # ツール定義（前回の記事から再利用） api_wrapper = WikipediaAPIWrapper(top_k_results=1, doc_content_chars_max=200) wikipedia_tool = WikipediaQueryRun(api_wrapper=api_wrapper) @tool def write_file(file_path: str, content: str) -> str: """指定されたパスにファイルを作成し、内容を書き込みます。""" try: with open(file_path, "w", encoding="utf-8") as f: f.write(content) return f"ファイル \'{file_path}\' に内容を書き込みました。" except Exception as e: return f"ファイル書き込み中にエラーが発生しました: {e}" tools = [wikipedia_tool, write_file] # 各エージェントのプロンプト researcher_prompt = hub.pull("hwchase17/react") analyst_prompt = "あなたは優秀なアナリストです。与えられた情報を分析し、要点をまとめてください。" writer_prompt = "あなたはプロのライターです。与えられた分析結果を基に、指定された形式でレポートを執筆し、ファイルに保存してください。" # エージェントの定義 def create_agent(llm, tools, prompt_template): return create_react_agent(llm, tools, prompt_template) researcher_agent = create_agent(llm, [wikipedia_tool], researcher_prompt) analyst_agent = create_agent(llm, [], analyst_prompt) # アナリストはツール不要 writer_agent = create_agent(llm, [write_file], writer_prompt) researcher_executor = AgentExecutor(agent=researcher_agent, tools=[wikipedia_tool], verbose=True, handle_parsing_errors=True) analyst_executor = AgentExecutor(agent=analyst_agent, tools=[], verbose=True, handle_parsing_errors=True) writer_executor = AgentExecutor(agent=writer_agent, tools=[write_file], verbose=True, handle_parsing_errors=True) # グラフの状態定義 class AgentState(TypedDict): input: str research_result: Annotated[List[str], operator.add] analysis_result: str report_path: str # ノード関数 def call_researcher(state): print("---CALL RESEARCHER---") task = state["input"] result = researcher_executor.invoke({"input": task}) return {"research_result": [result["output"]] } def call_analyst(state): print("---CALL ANALYST---") research_data = "\n".join(state["research_result"]) task = f"以下の情報を分析し、要点をまとめてください:\n\n{research_data}" result = analyst_executor.invoke({"input": task}) return {"analysis_result": result["output"]} def call_writer(state): print("---CALL WRITER---") analysis = state["analysis_result"] report_path = state["report_path"] task = f"以下の分析結果を基に、レポートを執筆し、ファイル \'{report_path}\' に保存してください:\n\n{analysis}" result = writer_executor.invoke({"input": task}) return {"output": result["output"]} ```

LangGraphでのワークフロー定義

次に、これらのエージェントを組み合わせてワークフローを定義します。今回は、リサーチャーが情報を収集し、アナリストがそれを分析し、最後にライターがレポートを執筆するというシーケンシャルな流れを構築します。

```python # グラフの構築 workflow = StateGraph(AgentState) # ノードの追加 workflow.add_node("researcher", call_researcher) workflow.add_node("analyst", call_analyst) workflow.add_node("writer", call_writer) # エッジの定義 workflow.set_entry_point("researcher") workflow.add_edge("researcher", "analyst") workflow.add_edge("analyst", "writer") workflow.add_edge("writer", END) # グラフのコンパイル app = workflow.compile() # グラフの実行 final_state = app.invoke({ "input": "AIエージェントの最新トレンドについて調査してください。", "report_path": "ai_agent_trend_report.txt", "research_result": [], "analysis_result": "", }) print("\n---FINAL REPORT---") with open(final_state["report_path"], "r", encoding="utf-8") as f: print(f.read()) ```

set_entry_pointで開始ノードを、add_edgeでノード間の遷移を定義します。ENDはグラフの終了を示します。

実行プロセスの追跡

verbose=Trueを設定することで、各エージェントの思考（Thought）、行動（Action）、観察（Observation）が詳細に出力されます。これにより、エージェントがどのように情報を処理し、次のステップに進んでいるかを追跡できます。

特にマルチエージェントシステムでは、エージェント間の情報の受け渡しが正しく行われているか、期待通りの役割分担が機能しているかを確認することが重要です。

エラーハンドリングと改善

マルチエージェントシステムは、単一エージェントよりも複雑なため、エラーが発生する可能性も高まります。以下のような点に注意して、エラーハンドリングと改善を行いましょう。

  • ツールの失敗: Web検索が失敗したり、APIがエラーを返したりした場合に、エージェントが適切にリカバリできるか。
  • LLMの出力形式の不一致: あるエージェントの出力が、次のエージェントの期待する入力形式と異なる場合。
  • 無限ループ: エージェントが同じ状態を繰り返し、タスクが完了しない場合。

これらの問題に対しては、プロンプトの改善、ツールの堅牢化、条件付きエッジによる遷移ロジックの調整などで対応します。

マルチエージェントシステム活用のコツ

マルチエージェントシステムを最大限に活用するためのヒントをいくつかご紹介します。

  • 役割の明確化: 各エージェントの役割と責任を明確にし、重複や漏れがないように設計しましょう。
  • コミュニケーションの最適化: エージェント間の情報伝達は、必要最小限かつ明確に行うように設計します。状態（State）の設計が重要です。
  • 段階的な構築: 最初から複雑なシステムを構築しようとせず、シンプルなシーケンシャルな連携から始め、徐々に複雑なロジックや並列処理を追加していくのが良いでしょう。
  • Human-in-the-loop: 重要な判断や、AIが苦手とする創造的なタスクには、人間が介入するステップを設けることで、システムの信頼性と品質を高めることができます。

マルチエージェントシステム利用時の注意点

マルチエージェントシステムは強力ですが、運用には注意が必要です。

  • 複雑性の増加: エージェントが増えるほど、システム全体の複雑性が増し、デバッグやメンテナンスが難しくなります。
  • コストの増大: 複数のエージェントがLLMを呼び出すため、API利用料金が単一エージェントよりも高くなる傾向があります。
  • パフォーマンス: エージェント間のやり取りが増えることで、タスク完了までの時間が長くなる可能性があります。
  • 協調の失敗: エージェント間のコミュニケーションがうまくいかないと、タスクが途中で停止したり、期待しない結果になったりすることがあります。
