# 【中級者向け】AIの突然の停止に備える！Claude Mythos 5緊急停止から学ぶ「プロンプト冗長化」実践ガイド

## 概要
2026年6月13日、米政府の命令によりAnthropicの最先端モデル「Claude Mythos 5」が突如提供停止となりました。特定の高性能モデルに依存するリスクが浮き彫りになる中、中級ユーザーに求められるのは「どのモデルでも同等の出力を得るための汎用性」です。本記事では、モデルの切り替えを前提とした「冗長性（Redundancy）プロンプト」の構築術を解説します。

## ターゲット
- 特定のAIモデルに依存した業務フローを構築しているエンジニア
- AIのアップデートや停止による業務停止リスクを最小化したいビジネスパーソン
- 複数のLLMを使い分け、常に最適な結果を追求したい中級ユーザー

## 記事のポイント
1. **依存リスクの可視化**: Claude Mythos 5停止が投げかけた「シングルポイント故障」の課題。
2. **モデル非依存プロンプトの設計**: 特定のモデル固有の癖を排除し、構造化データ（JSON等）を確実に引き出す記述法。
3. **「プロンプト・トランスパイラ」思考**: 1つの指示を、ChatGPT(o3)、Gemini(2.0 Pro)、Claude(Fable)のそれぞれに最適化して同時実行するワークフロー。
4. **フォールバック戦略**: メインモデルがエラーを返した際に、自動で代替モデルに切り替えるための指示構成。

## プロンプト例
- 「以下の要件を、特定のモデルのバイアスを排除した『ニュートラル・インストラクション』に変換して。出力は常にRFC 8259準拠のJSON形式とし、モデルを切り替えても構造が崩れないように制約を定義して」
- 「Claude Mythos 5で実行していた以下のワークフローを、GPT-5.5とGemini 2.0で再現するための共通プロンプトを作成して。各モデルのトークン制限や推論の癖を吸収するラッパー指示を含めて」
